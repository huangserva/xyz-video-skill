## 核心理念

**思考在母模型脑子里完成，不甩给生图模型。**

母模型是导演。它设计了每个 shot 的姿态、情绪、构图、视线——这些画面在它脑子里。它应该把脑子里看到的画面用精确的语言写出来，交给生图模型执行。

生图模型不会思考，只会执行。给它越精确的画面描述，出来的图越接近导演的设想。

## 问题：当前链路缺了什么

```
当前：
母模型写 storyboard → 退出
Python 脚本机械拼装 prompt → Flash 提取/翻译 → 甩给 Gemini 生图 → 直接进视频

缺的：
母模型写 storyboard → 导演逐帧写画面 prompt → 生图 → 导演审片 → 通过/重来 → 进视频
```

母模型不应该"写完 storyboard 就走"。它应该是全程在场的导演——写 storyboard、写帧 prompt、审片，贯穿始终。

```
步骤7:   合成                          → Python 脚本
```

## 步骤 4.5：导演写帧级 prompt

### 导演思考协议

对每个 shot 的每一帧（首帧 / 关键帧 / 尾帧），母模型按以下顺序思考：

**1. 闭上眼睛，想象这个画面**

- 这是第几拍？之前一拍画面是什么样的？
- 这个镜头要表达什么情绪？观众此刻应该感受到什么？

**2. 你看到了什么？**

- 构图：主体在画面什么位置？占多大比例？
- 光线：从哪个方向来？什么质感？
- 人物：什么姿态？什么表情？视线看向哪里？
- 环境：前景/中景/远景有什么？

**3. 把这个画面写出来**

- 写画面，不写故事（不是"她心生怜悯"，而是"她的表情从警惕变为柔和，眉头舒展"）
- 写状态，不写过程（不是"她走向亭子"，而是"她站在亭子入口，身体朝向亭内"）
- 写精确，不写模糊（不是"远处有个人"，而是"画面右三分之一处，一个模糊的人影，只露出轮廓"）

### director_prompts.json 结构

```json
{
  "shots": {
    "1": {
      "first_frame": "画面左侧三分之一，女孩半蹲在崖壁根部，身体重心落在右脚和墙根之间，右手自然垂在膝上。她的视线越过画面中心，投向右侧远处的崖壁方向。背景是灰蒙蒙的雨天崖壁，近处有碎石和枯草。中景偏右，一把油纸伞从画面边缘切入，只露出伞面边缘和持伞的手。整体色调偏冷灰，只有伞面带一点暖黄色。",
      "keyframes": [
        {
          "timestamp": 3.0,
          "prompt": "女孩的头部开始转向右侧，上身微微跟着转动，但下半身和手的位置保持不动。视线已经从远处的崖壁收回到画面中景位置——她在寻找声音的来源。表情处于茫然和警觉之间，眉头微皱。"
        }
      ],
      "last_frame": "女孩的身体姿态未变，但视线已经完全转向画面右侧近处——她的瞳孔微微放大，嘴唇微张，表情从茫然变为警觉。伞的位置比首帧更靠近画面中心，能看到更多伞面和一只握着伞柄的手。伞下区域出现一圈柔和的暖色光晕。"
    },
    "2": {
      "first_frame": "...",
      "keyframes": [],
      "last_frame": "..."
    }
  }
}
```

### storyboard 与 director_prompts 的分工

| 文件 | 写什么 | 服务于 |
|------|--------|--------|
| storyboard.json | 故事 + 约束 + 结构 + 连续性事实 | 生成计划 + 审片检查清单 |
| director_prompts.json | 每一帧的精确画面描述 | 图片生成的直接输入 |

- storyboard 回答"这个 shot 要做什么、有什么约束"
- director_prompts 回答"这一帧画面上到底长什么样"

同一个 shot，两种视角：一个是导演的计划书，一个是导演脑海里看到的画面。

## 步骤 5：素材生成（改动）

### 之前

```
storyboard.json → _extract_all_shot_prompts(Flash) → build_image_prompt → 生图
```

### 之后

```
storyboard.json + director_prompts.json → 直接用帧级 prompt → 参考图绑定 → 出镜控制 → 生图
```

### `_extract_all_shot_prompts` 可以去掉

母模型在步骤 4.5 已经做了 Flash 做的事情——而且做得更好：
- 母模型理解完整故事
- 母模型知道前后镜头画面
- 母模型按导演思维写画面，不是机械提取
- 不需要翻译，全程中文

### `build_image_prompt` 简化为

```
帧级 prompt（来自 director_prompts，画面描述）
+ 参考图绑定（角色/场景/道具的参考图路径）
+ 出镜控制（谁出现）
= 图片生成 prompt
```

不再需要：约束块、scene_continuity、shot_delta、pose_contract、gaze_contract 的文本拼装。这些留给审片。

## 步骤 5.5：导演审片

### 审片节点

图片生成后，母模型拿着生成的图 + storyboard + 自己的 director_prompts 审片。

### 审片检查清单

这个清单就是之前从图片 prompt 里拿出来的那些约束——现在它们终于到了正确的位置：

| 检查维度 | 数据来源 | 审什么 |
|---------|---------|--------|
| 出镜控制 | `subject_constraints` | 该在的在不在？不该在的有没有出现？ |
| 姿态 | `pose_contract` | 身体重心、支撑关系对不对？ |
| 视线 | `gaze_contract` | 看的方向对不对？ |
| 构图 | `motion_control` | 朝向、镜头角度对不对？ |
| 场景连续性 | `scene_continuity` | 空间关系有没有漂移？道具状态对不对？ |
| 变化边界 | `shot_delta` | 有没有发生不该变的变化？ |
| 角色一致性 | `consistency_anchors` | 关键识别特征都在不在？ |
| 叙事意图 | `director_plan` | 这张图有没有表达出戏核？ |
| 情绪 | `emotion_arc` | 情绪基调对不对？ |
| 衔接 | 前后 shot 状态 | 跟上一帧接得上吗？ |

### 审片决策

```
审片结果：
  1. 通过 → 进入下一环节
  2. 标记问题 + 定位原因：
     - 问题在 prompt → 调整 director_prompt 重新生成
     - 问题在参考图 → 回到步骤 3 修参考图
     - 问题在 storyboard 设计 → 回到步骤 4 修改设计
  3. 整体方向不对 → 回到步骤 4 重新设计
```

母模型不只能说"这张不对"，还要说"为什么不对"和"怎么改"。

### 母模型为什么适合做审片

**1. 意图理解**

母模型自己写的 storyboard，它知道为什么这个 shot 是 `offscreen_reaction`——因为它在设计时就决定了"这里要制造悬念"。Flash 只能看到约束字段，不理解意图。

**2. 上下文连续性**

母模型从 story → framework → storyboard → director_prompts 一路写下来，脑子里有完整的故事线和画面记忆。审第 5 个 shot 时，它知道前 4 个 shot 画面上是什么样的。Flash 每次调用都是独立的。

**3. 创造性判断**

有些问题不是约束违反，而是"技术上没问题，但感觉不对"。比如一个"递伞"的镜头，姿态都对、构图也对，但角色的表情太冷漠，不像"心生怜悯"。这种创造性判断只有理解故事的母模型能做。

**4. 经验积累**

审了前几个 shot 后，母模型会发现"这个图片模型总是把武器画错"或"构图偏右的问题反复出现"，然后在后续 shot 的 director_prompt 里主动补偿。这是"学会思考"——从审片经验中学习，调整后续的生成策略。

## 生成层 vs 审查层：统一数据，两种读法

同一份 storyboard 数据，生成层和审查层读法不同：

```
生成层读 storyboard → 提取"画什么"
  - intent（这张图要表达什么）
  - 出镜控制（谁出现）
  - 画面描述（来自 director_prompts）
  - 参考图绑定
  → 简洁、正向、画面驱动

审查层读 storyboard → 提取"对不对"
  - subject_constraints（出镜检查）
  - pose_contract（姿态检查）
  - gaze_contract（视线检查）
  - scene_continuity（连续性检查）
  - shot_delta（变化边界检查）
  - consistency_anchors（一致性检查）
  → 完整约束、逐项检查、创造性判断
```

## 完整流程图

```
母模型                                          Python 脚本
  │
  ├─ 步骤1: story.json
  │
  ├─ 步骤2: framework.json
  │
  │                          ──── 步骤3: 角色参考图 ────→
  │                          ←── 母模型审片（参考图质量）──
  │
  ├─ 步骤4: storyboard.json
  │    （含约束、pose_contract、
  │     gaze_contract、shot_delta 等）
  │
  ├─ 步骤4.5: director_prompts.json
  │    （逐帧画面级 prompt，
  │     导演思维写的，不是代码拼的）
  │
  │                          ──── 步骤5: 素材生成 ──────→
  │                               读取 director_prompts
  │                               直接生图，不再 Flash 提取
  │                          ←── 母模型审片（图片质量）──
  │                               对照 storyboard 约束检查
  │                               通过/调整/重来
  │
  │                          ──── 步骤6: 视频生成 ──────→
  │                          ←── 母模型审片（视频质量）──
  │                               粗筛 + LLM 判断
  │
  │                          ──── 步骤7: 合成 ──────────→
```

## 一句话总结

**这不是"小优化"。这是把 skill 从"代码拼 prompt"升级为"母模型实时导演"。**

- 母模型从"写完 storyboard 就走"变成"全程坐在监视器前"
- 思考在母模型脑子里完成，生图模型只管执行
- 约束从"塞进 prompt 让模型遵守"变成"审片时让导演检查"
- 每一帧的 prompt 是导演脑子里看到的画面，不是代码从 JSON 里拼出来的
